# 侧边对话

## 当前产品行为

Vera `v0.1.6` 已内置一个引用伴聊（quote companion）：它在最新完成的回合处 fork 当前活动 Session，继承模型、工作区上下文和权限配置，从会话列表中隐藏它，并在面板关闭时移除它。

通用的侧边对话入口扩展了这一基础：

- 标题栏无需选中文本即可打开侧边对话；
- 命令面板把侧聊作为一等动作暴露，键盘快捷键与工作栏启动器显示的相同；
- `/side` 打开空侧聊，而 `/side <prompt>` 创建带标题的侧聊并把该 prompt 作为首轮发送；
- Composer 的 `/` 建议层以图标和描述暴露侧聊；选择它执行命令并移除查询，而不是创建假的 Skill token；
- 空侧聊采用其首个被接受的 prompt 作为标签标题，并在后续追问和面板移动中保持标题稳定；
- 选中会话记录文本仍会把引用上下文追加到同一面板；
- fork 在面板打开时立即创建，在 Composer 获得焦点前有短暂的准备状态；
- 子会话接收 `mode:side_conversation` 标签，它添加一个系统边界，声明继承的父会话历史仅作参考；
- 主 Session 及其活动回合独立继续；
- 只有侧聊中提交的指令生效；明确的侧聊动作可以使用继承的权限配置，权限可以从侧聊 Composer 更改；
- 运行中的侧聊回合在下一个模型步骤接受 Steer 消息，同时 Stop 仍然可用；
- 侧聊 Composer 与主 Composer 共享 `/` 技能发现、`@` 文件引用、文件、引用和草稿所有权；
- 已确定的侧聊回答暴露 Copy、Info 和 Regenerate，而不会把用户导航出临时侧聊标签页；
- 面板关闭时删除侧聊 Session；
- 每个创建的临时 fork 都注册到主进程的清理权威，因此进程级中断会在重启时移除孤儿。

## Codex 参考

Codex 把 `/side` 实现为临时线程 fork。

TUI 使用带 `excludeTurns` 的 `thread/fork`，注入隐藏的边界项，保持独立的父/侧 UI 状态，并在清理期间中断并退订侧线程。Desktop 应用把 fork 标记为 `sideConversation`，在 `sidechat:<thread-id>` 右侧面板标签页中打开它，将其排除在最近对话界面之外，并在永久关闭非空临时聊天前进行确认。

主要参考：

- `openai/codex#18190` 引入了 `/side`。
- `openai/codex#34198` 停止在侧聊 UI 中重放继承的回合。
- `openai/codex#35011` 在切换到其父会话时保持侧边对话打开。
- `openai/codex#35887` 把中断/退订清理移到后台。

## Desktop 架构快照

2026-08-06 检查的当前本地 Codex Desktop 快照是应用构建 `26.730.61639`（bundle 构建 `6234`，打包于 2026-08-05）。它的侧聊是通用应用外壳面板系统中的一种标签页类型，而不是专用抽屉。

外壳创建独立的 `right` 和 `bottom` 标签页控制器。每个控制器拥有：

- 有序的标签页 id、活动标签页、逐标签页状态和激活历史；
- 打开、激活、关闭、关闭其他、关闭右侧、重排和固定；
- 通过 `moveTabTo` / `receiveMovedTab` 在控制器之间移动标签页；
- 预览标签页，除非被固定，否则会被下一个预览替换；
- 携带组件、props、图标、标题、关闭钩子、移动钩子、上下文菜单项和可选持久路由的标签页描述符。

关闭活动标签页不只是选择下一个数组项。控制器跟踪开启者关系和最近的激活记录，因此子标签页可以先返回其开启者，再回退到相邻标签页。

持久化布局是包含 right 和 bottom 标签页顺序、活动 id、打开状态、焦点区域、全宽状态和可恢复路由的拓扑快照。预览标签页被排除。浏览器标签页额外持久化浏览器存储 id、恢复 URL、设备工具栏状态和目标面板。

因此，新标签页页面是可用标签页类型（Review、Terminal、Browser、Files、侧聊以及按功能开关控制的添加项）的注册表面，而不是与侧聊功能绑定的固定菜单。

## Desktop 侧聊生命周期

打开新侧聊首先安装不可关闭的 `sidechat-loading:<parent>:<index>` 标签页。然后 fork 最新的父状态，并用 `sidechat:<conversation-id>` 替换加载标签页。

Vera 现在在保持其稳定面板 id 的同时匹配该用户可见的加载契约：标签页显示 spinner，在立即 fork 就绪前不能关闭、拖动、重排或移动。之后它变成普通的可关闭侧聊标签页，且不重新挂载面板草稿。

fork 被同时标记为临时和侧边对话，被排除在最近对话界面之外，并接收一个开发者边界，该边界：

- 把继承的历史和工具视为仅参考；
- 只激活在侧聊边界之后提交的指令；
- 禁止继续父工作或使用子智能体；
- 默认允许非修改性检查；
- 只有当用户在侧聊中明确请求时才允许修改。

侧聊标签页可以在 right 和 bottom 面板之间移动。关闭非空临时侧聊会运行 `onBeforeClose` 确认（带持久化的「不再询问」偏好），然后在其关闭钩子中从缓存丢弃该对话。已保留的侧聊可以恢复并选择加入 `preserveOnClose`。

面板可见性控制器刻意区分隐藏、关闭和移动：

- 激活或打开标签页会显示其目标面板；
- 加载标签页意味着新创建的侧聊会立即显示面板；
- 手动隐藏面板会保留其标签页、活动标签页、草稿和流；
- 选中文本的追问先搜索 right 面板，再搜索 bottom 面板，优先使用每个面板的活动侧聊，然后才是其第一个侧聊；
- 关闭一个标签页时，若还有其他标签页，面板保持打开；
- 关闭最后一个标签页会关闭面板；
- 移出最后一个标签页不算关闭它，因此源面板可以在其新标签页页面上保持打开，同时目标面板打开。

被检查的 right 和 bottom 可见性原子默认为关闭，且没有 localStorage 偏好支撑。标签页和路由恢复是与面板当前是否可见分开的机制。

当前产品仍有已知的恢复和焦点缺口。上游开放的 issue 涵盖无法恢复的已关闭聊天、闲置后过期、主与侧输入区之间的焦点切换，以及涉及多个侧聊加 Browser 标签页的崩溃。Vera 不应仅为视觉对等而复制这些失败模式。

被检查的 Desktop bundle 注册了一个 id 为 `side` 的 Composer 斜杠命令。其解析器只接受 `/side` 或 `/side <prompt>`。非空 prompt 被净化后用作标签页标题，并作为首个侧聊回合发送。该命令在侧聊内部以及父对话存在之前不可用。当前 Desktop bundle 不注册 `/btw`；该别名属于其他 Codex 界面。

## Codex Terminal 架构

同一个 Codex 构建使用真正的 xterm 界面，而不是覆盖终端结果卡片的命令字段。renderer 加载 xterm、`FitAddon`、`WebLinksAddon` 和 `ClipboardAddon`。每个终端拥有稳定的会话 id，并由携带 cwd、主机 id 和会话 id 的持久路由的动态 `terminal:<session-id>` 标签页表示。

renderer 不拥有进程。单例终端控制器拥有：

- 会话到终端会话与终端会话到会话的映射；
- 活动会话选择和编号标签页标题；
- 有界的原始 ANSI 重放缓冲区加实时流监听器；
- 在宿主会话和 renderer 监听器都就绪前挂起的写入；
- 终端尺寸、工作区绑定、标题和用户交互状态；
- 跨 xterm 卸载/重挂的 DEC 备用屏幕模式。

主进程拥有本地 `node-pty` 和远程进程会话后端。它强制执行窗口归属，创建或附加会话，流式传输原始数据，调整大小，写入，关闭，并保留有界的重放缓冲区。在 right 和 bottom 面板之间移动标签页会重挂或重新定位 xterm 视图，而 PTY 仍处于同一个主进程会话下。关闭标签页即关闭会话。打开另一个 Terminal 会创建另一个 PTY 和另一个动态标签页。

动态验证与静态链路一致：在被检查的构建中打开 right 和 bottom Terminal，会在不同 PTY 上创建两个直接子登录 shell。两个界面同时保持活动。

## Codex Review 架构

Codex 使用一个固定的 `diff` 标签页，其源在面板内变化。它不是工具结果消息的聚合。Review 模型对仓库快照发出 Git 查询，并支持：

- 分支、最后一轮、未提交、已暂存、未暂存和提交源；
- 目标分支选择和多仓库选择；
- 带快照世代和过期快照拒绝的逐文件批量 `review-diff` 请求；
- 刷新、跳转到文件、统一/分栏视图、换行、空白过滤、全文件加载和富预览；
- 在区块、文件、hunk 范围内的暂存、取消暂存和还原动作。

最后一轮可以聚合所有仓库的更改。Git 支持的源可以独立禁用，而最后一轮仍可从对话 diff 状态获得。Vera 现有的 `ToolResultPreview` 仍是值得复用的好渲染器，但持久化的 `file_diff` 工具结果不是等价的数据权威。

## Vera 对等状态

Vera 现在拥有同一架构的第一个可用切片：

- 动态右侧标签页状态，而不是固定标签页联合；
- 由注册表支持的新标签页页面，而不是固定标签页切换器；
- 侧边对话优先的新标签页页面，随后是 Review、Terminal、Browser、Files，然后是 Vera 特有的 Tasks 和 Trace；
- Review 现在在一个固定标签页内有 Branch、Unstaged、Staged 和 Last Turn 源；
- Branch 暴露明确的基准分支选择器；
- Branch、Unstaged 和 Staged 使用从 Session cwd 派生的主进程 Git 快照权威；renderer 不能提供 cwd 或任意 Git 命令；
- Branch 在可用时解析不同的本地/默认分支，并包含已提交的分支更改、已暂存更改、未暂存更改和未跟踪文件；
- 快照受文件和 diff 字节限制约束，并携带修订哈希；Stage 和 Unstage 重新读取该修订，在修改索引前只接受权威快照中存在的路径；
- 未暂存文件可以在破坏性确认后还原；
- Last Turn 复用最近一个产生持久化 `file_diff` 结果的回合，通过同一个高亮 diff 渲染器；
- Terminal 现在是由 xterm 和 `FitAddon` 支持的动态 `terminal:<ref>` 多标签页界面；
- 现有 ShellRun 进程管理器仍是唯一的进程、调整大小、停止、持久化和 Runtime 资源权威；
- ShellRun 额外向 Desktop 发布带序列的原始 PTY 增量和有界重放快照，而模型/工具界面继续使用净化后的持久屏幕快照；
- 在 right 和 bottom 面板之间移动 Terminal 会保留 PTY 和 xterm 输出；关闭其标签页会停止 PTY；
- Terminal 标签页被刻意排除在静态布局持久化之外，因为 ShellRun 进程不会在应用重启后存活；
- 集成的登录 shell 抑制 oh-my-zsh 的自动更新提示，因此它不会吞掉第一条输入的命令；
- 标题栏启动器和面板切换动作；
- 带 `side`、`btw`、`侧聊` 和 `追问` 搜索词的命令面板侧聊动作；
- Composer `/side` 和 `/side <prompt>` 处理，自动发送首回合并使用由 prompt 派生的临时标签页标题；
- 在与 Skills 相同的触发层进行 Composer 侧聊斜杠菜单发现，不改变 Skill token 序列化或草稿所有权；
- 从标题栏、启动器、命令面板或选中文本流程打开的侧聊采用首条 prompt 作为标题；
- 立即 fork 准备期间不可关闭、不可拖动的加载标签页；
- 按类型稳定的标签页图标，侧聊在回合活动时从正常图标切换到 spinner；
- 每个面板有一个用于自动打开产物的可替换预览标签页；手动打开它、双击其标签页、使用其上下文菜单的 Pin 动作或与其内容交互会把它转换为普通标签页；
- 预览标签页在固定前被排除在布局持久化之外；
- 带相邻回退和重复打开激活的可关闭标签页；
- 最近的激活历史，因此关闭标签页会先返回用户来自的标签页，再回退到相邻标签页；
- 指针拖动重排加上下文菜单的左移 / 右移动作；
- 带 ArrowLeft、ArrowRight、Home 和 End 的标准桌面标签页键盘导航；
- 新标签页焦点交接、ArrowUp/ArrowDown/Home/End 菜单导航，以及 Escape 返回先前活动的标签页；
- 独立的 right 和 bottom 面板控制器，活动标签页可同时存在；
- 保留侧聊 fork/草稿/流和 Browser 页面状态的跨面板标签页移动；
- 持久化的 right/bottom 静态标签页拓扑、面板可见性和 bottom 面板高度，包括 v2 右侧面板迁移；
- 带批量侧聊确认和清理的上下文菜单关闭、关闭其他和关闭右侧动作；
- 持久化的静态标签页顺序和活动标签页，侧聊被排除；
- Browser、Files 和侧边对话快捷键；
- 工作栏折叠或新标签页页面活动时保留侧聊草稿和流式状态；
- 多个编号侧聊标签页，带独立的草稿、fork、流和引用队列；
- 与主对话相同的 Composer 外壳，包括功能性的附件菜单、Skill 和文件提及、继承的权限菜单和回合中 Steer 提交；
- 用于 Copy、Info 和 Regenerate 的相同回答元数据界面，Branch 被扣留，因为它会导航出临时侧聊标签页生命周期；
- 没有内容区关闭动作：侧聊生命周期完全属于标签页 chrome 及其关闭确认；
- 带持久化「不再询问」偏好的非空关闭确认；
- 侧聊标签页关闭或其所属会话更改时的 fork 清理；
- 对因应用进程中断而成为孤儿的临时 fork 的启动清理。

Vera 现在还镜像 Codex 的面板过渡规则：隐藏保留活动标签页，关闭最后一个标签页会关闭该面板，移出最后一个标签页会让源面板停留在新标签页，选中文本优先复用右侧侧聊而非底部侧聊。Vera 刻意继续在重启间持久化通用工作栏可见性；Codex 的被检查可见性原子在内存中。

### 插入消息渲染

首个侧聊转向（steering）实现正确交付了插入的文本，但错误地投影了它。`steering_message` 与原始 prompt 共享活动回合 id。已确定的回合投影只存储一个 `turn.user`，因此后来的转向行替换了 prompt；实时投影也忽略了 `steering_message`，使插入的文本在确定之前不可见。

回合现在保留其第一个用户行作为 prompt，并把同一回合后来的用户行投影为 `userInterjections`。实时投影在 Runtime 确认转向后立即添加转向插入行，确定的覆盖层按消息 id 去重该乐观行。侧聊回归测试要求两个用户气泡在插入后立即出现，并在助手响应确定后仍然存在。由于修复位于共享的回合投影中，主对话获得相同行为。

## 验证说明

renderer 生产构建仍在工作栏边界处拆分。在面板生命周期更改之后，直接 `gzip -9` 测量报告 `session-workbar` 块为 22,237 字节，主 `index` 块为 75,703 字节，两者都略低于之前的 22,260 字节和 75,801 字节快照。

它还没有通用的持久路由恢复，也没有离开所属会话后的保留侧聊恢复。Terminal 启动保持本地化并刻意受限：renderer 可以为当前 Session 请求登录 shell，但还不能选择远程主机、任意启动命令或 cwd。Review 仍缺少提交源浏览、hunk 级动作、文件系统监视和多仓库聚合。

视觉外壳是低到中等难度。完整的控制器对等是另一个中到高等工作量，因为它改变每个工作栏界面的归属、持久化、焦点和清理行为。

## UI 与性能验证

面板外壳在浅色和深色主题下以 320px、约 480px、600px 以及底部放置方式进行了检查。那次检查中发现的两个布局 bug 已在其归属边界修复：

- Astryx Toolbar 的开始槽保持其固有标签页宽度，因此缩窄面板会把新标签页按钮推出面板。工作栏现在约束该槽，并且只滚动标签页列表，绝不滚动外层面板。
- 共享的 Composer 页脚在 320px 时把模型换行到第二行。右侧侧聊现在使用紧凑的单行页脚，继承的模型省略显示并有响应式 160px 上限；更宽的底部面板保持正常的 Composer 几何。

立即 fork 也有一个简短的可访问准备状态。就绪后，空会话记录返回到与普通聊天相同的空白状态，侧聊 Composer 获得焦点。还针对同一工作区重启了一个被中断的开发进程，以验证其孤儿 fork 在会话列表渲染前被移除。

最新的视觉检查覆盖了深色命令面板、深色右侧面板的加载和就绪状态，以及浅色底部面板状态。加载标签页保持稳定的占位，忙碌时移除其关闭提示，并在 fork 提交后恢复正常的标签页 chrome。

活动回合检查确认侧聊在处理期间只把其标签页图标改为 spinner。回合期间关闭提示保持可用，之后正常的侧聊图标返回，而不改变标签页标题或布局占位。

`/side <prompt>` 视觉检查还确认该命令绝不出现在父会话记录中，prompt 在侧聊会话记录中发送，标签页使用 prompt 作为省略显示的标题，悬停时显示完整标题。

最终开发应用检查中发现的一个真实模型失败有两个独立原因：

- 活动工具结果归档占位符使用了带 `sha256` 和 `bytes` 查询参数的 URI；Nemotron 把产物 id 和哈希复制到其 `ArchiveRead` 调用中，但丢弃了第二个查询参数，因此严格解析器返回 `invalid_ref`；
- 侧聊 fork 选择了最新的非运行父回合，其中包含失败和中止的回合。因此，对较弱的模型而言，简短的侧聊 prompt 可能看起来像是未完成父工作的延续。

归档引用现在把产物 id、哈希和字节长度编码为路径段，而解析器仍接受旧的查询形式以保持持久化兼容。侧聊 fork 现在只通过最近成功完成的父回合继承，在没有已完成回合时从空开始。一次真实的 Nemotron 验证分三次成功分页读取了一个 10,982 字符的归档结果，而在中止的父回合之上打开的新侧聊直接回答了「你好」，没有调用 Glob、Read 或 ArchiveRead。

斜杠建议检查确认 `/si` 在 Composer 上方渲染一个单独的侧聊命令，带正常的侧聊图标和说明性辅助文本。键盘选择清除查询并打开空侧聊。

已实现界面上的实测性能检查：

- 含 84 个更改文件的 Git Review：Branch 中位数从 335ms 提升到 90ms，Unstaged 从 229ms 提升到 69ms。
- 220 个文件的未跟踪快照保持在 200 个文件的限制内，36.4ms 内完成，并增加了约 5.3MB 堆。
- Review 以每页 20 个挂载文件 diff。
- 5MB PTY 流从 5,120 个 renderer IPC 事件降至 80 个，同时保留每一个字节。聚焦的 Runtime 合并测试也把 1MB 流保持在 32 个事件内。
- 在实测的生产构建中，加载标签页、命令面板、`/side`、斜杠建议、动态标题和标签页图标打磨为主 renderer 块增加了约 0.70KB gzip，为懒加载工作栏块增加了约 0.28KB gzip。
- 嵌套懒加载边界随后把 `session-workbar` 块从 120,835 字节 gzip 减少到 21,832 字节 gzip，约 82%。Terminal 现在是 86,747 字节的按需块，Files 是 7,756 字节，Review、Browser 和 Trace 是独立的 2.4-4.3KB 块。主 `index` 块从 75,717 移动到 75,941 字节 gzip，增加了 224 字节。

19 项测试的工作栏交互套件涵盖侧聊、斜杠和命令面板入口、Review、Terminal、标签页重排、面板移动、持久化和 320px 布局。共享 UI 套件通过 432 项测试，13 项测试的 Skill/提及 E2E 套件确认把侧聊添加到 `/` 菜单没有改变 Skill token 或草稿行为。完整的 Runtime 和 Desktop 套件在持续机器负载下可能暴露对时序敏感的子进程测试；本次检查中观察到的每个此类失败在单独重跑时都通过了。
